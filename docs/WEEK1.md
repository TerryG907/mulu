# Mulu 第一周：从扫描书到可点击目录，一条命令

## 结论

- 新增 6 个命令：扫描书只要告诉 mulu 印刷目录在哪几页，`mulu auto` 就能认字、分层级、算页码偏移，再把目录写进 PDF，原文件的字节一个不改。
- 13 本合成扫描书里，12 本自动写出了目录。这 12 本的书签全部正确：页码、层级都对，标题错字率约 0.01%。剩下 1 本（`zh_chem_noisy`）扫描太脏，mulu 主动拒绝，没有乱猜。页码偏移 13 本全对。
- 两轮对抗评审共提出 22 个问题（严重 2、重要 10、次要 10），**全部修好**，每个都有回归检查。修复过程中又发现并修好 1 个退步。
- **要说清楚**：这些书是程序生成的，印刷整齐、没有真实纸张的毛病，所以上面的数字只是**上限**。真书效果如何，要等你用自己的扫描书跑一遍闸门（见最后一节）。

## 新命令

| 命令 | 做什么 |
|---|---|
| `mulu ocr-toc 书.pdf --pages 5-7` | 用 macOS 自带的 Vision 识别印刷目录页，每个条目输出一行，例如 `第一章 绪论<TAB>1` |
| `mulu toc parse raw.txt --offset N` | 把印刷目录文字转成 Mulu 目录：推断层级，把印刷页码换成物理页码。`--offset auto --pdf 书.pdf` 会自动找偏移 |
| `mulu detect-offset 书.pdf` | 抽样 24 页正文，识别页眉页脚里的页码，投票得出「物理页 − 印刷页」，输出 JSON |
| `mulu auto 书.pdf --toc-pages 5-7 -o 输出.pdf` | 全流程。每一步做了什么都会打印出来；没把握时拒绝，退出码为 2，不产生输出 |
| `mulu toc convert …` | 在 PdgCntEditor/PDFPatcher 的 XML、pdfdir、OPML、JSON 和 Mulu 格式之间转换 |
| `mulu export-outline 书.pdf --format …` | 把 PDF 里已有的目录导出来 |

端到端示例（目录印在第 5–7 页）：

```bash
mulu auto 书.pdf --toc-pages 5-7 -o 书-带目录.pdf --toc-out 目录草稿.txt
```

如果 mulu 拒绝了，`目录草稿.txt` 里仍然有识别出的目录，可疑的行前面标着 `# ?`。手工改好后，用 `mulu apply 书.pdf 目录草稿.txt -o 书-带目录.pdf` 写入。

## 速度（M5 Pro，`nice -n 15` 低优先级，你同时在用电脑）

- 识别目录页：`ocr-toc` 每页约 1 秒。密集的正文页约 2.5 秒，因为每页要用 200、300、400 dpi 各读一遍。
- 找偏移：`detect-offset` 每本 2–4.5 秒，和书的厚度无关（2000 页的书也只要 2.0 秒）。
- 整本 `mulu auto`：每本 4–16 秒，13 本平均 7.5 秒。120 页的扫描书 9.4 秒，2000 页的书 12.3 秒。内存峰值 350–400 MB。
- 写入本身仍然是毫秒级。

## 发现并修好的问题

严重：
1. 章标题行没有页码时，`auto` 会把第一章指到目录页本身，而且报告「0 条可疑」。现在目录页和它之前的页永远不会被当成章首页。
2. 书中间夹了 4 页以上没有页码的插页时，`detect-offset` 已经说了「偏移可能在书中间变化」，`auto` 却仍然写出目录，后半本的书签整体错 4–8 页。现在只要抽样页里存在另一个有分量的偏移，`auto` 就拒绝。

重要：
3. 标题折行、第一行又以数字结尾（「3.2 回顾20 / 世纪的经济史」）时，会被拆成两个错的书签。现在合并成一条，并给出警告。
4. 「28 至 35」这种中文页码范围会取成 35。现在和「12-15」一样取首页 28。
5. 以数字开头的无编号标题（「3D打印技术」「5G网络」）会被错放到下一层。现在和同一缩进的兄弟条目放在同一层，标题原样保留。
6. 识别时丢了空格的「1.21.5万亿投资」，现在拆回「1.2 1.5万亿投资」并标记。
7. 标题里残留的引导线（「组织-----------」「附则==」）现在会去掉。
8. 目录范围里带上了「图表目录」时，会把真正的目录判成顺序错乱。现在图表目录会被识别出来并跳过。
9. 折行标题被目录页的页码「iii」和「目录（续）」隔开时，现在能正确合并。
10. 8 号小字的密集目录会丢掉整列页码。现在能读出来：写出 93 个书签，其中 3 个标为可疑，包括 1 个多认出来的「试」。
11. 英文标题以 Problem、Part、Chapter 等词结尾时，TAB 后面的页码会丢失，现在保留。
12. 偏移只在书尾变化（插页在最后约 12% 的正文里）时，会被判成「有把握」。现在最后连续 2 个抽样页都指向另一个偏移，就拒绝。

次要：「Index 索引」的层级；「①」放到「(1)」下一层；以「——」开头的副标题并入上一行；把误认的「日录」和「Chapter … Page」表头当成目录标题丢掉；`toc parse` 能认出索引页；目录在书末、页码从封面连续编、目录页底有脚注这三种正常书，不再被误拒；某一页渲染失败只跳过这一页，不再整个中止；`--pages`/`--toc-pages` 最多 40 页，不会一不小心识别整本书；`-o` 指向文件夹或只读目录时，在识别开始之前就报错；`auto` 以前在只有 3/24 个抽样页一致时也会接受偏移，现在这个门槛写成了明确规则，只要抽样里出现另一个有分量的偏移就拒绝。

这一轮修复中新发现的退步：在「之一 ………… 50」这种短标题后面跟一长串引导点的行里，Vision 会把「之一」读成「17」，或者干脆读不出来，于是这个条目丢失（`zh_essays_unnumbered` 从全对掉到 98%）。现在会只截取引导点之前的文字，放大 2 倍和 3 倍各读一次，两次一致才采用，而且这一条会被标为可疑。这本书已恢复全对。

回归检查：`swift test` 185 个测试全部通过（其中 13 + 6 个是这一轮新加的复现用例）。`tools/run_all.sh` 78 行全部通过。`tools/run_all.sh --books` 全部通过，其中包括新加的 `tools/eval/week1_regress.py`：每个评审问题对应一项或几项检查，共 56 项。闸门自检 `tools/gate/selftest.sh` 结果为 ALL OK。

## 还弱的地方

- **真实扫描没测过。**合成书的字体干净，纸面平整，没有阴影和装订弯曲。真书的识别错字率一定更高，拒绝的书也会更多。
- 下面几种情况目前会拒绝，这是安全的，但得不到目录：页码印在标题**左边**的目录；每个中文条目后面跟一行英文的双语目录；会议论文集那种标题下面还有作者行的目录；页码紧贴在以数字结尾的标题后面（「iPhone 1512」）；英文标题里含罗马数字，又碰上识别不清（「Henry VIII」）；前言单独从 1 开始编页码。
- 书中间夹了没有页码的插页时，**只会拒绝**。分段偏移还没做，这种书只能先手工加 `--offset`，再改草稿。
- 标题偶尔会有 1 个错字（492 个书签里有 3 个），页码和层级不受影响。用之前最好扫一眼。
- 很脏的扫描（错字率 20% 以上）会直接拒绝，只能手工校对草稿。

## 真实扫描闸门：请你来跑

完整说明在 `tools/gate/README.md`。步骤如下：

1. 把 10 到 30 本扫描 PDF 放进同一个文件夹，来源尽量分散：扫描仪直接输出的、超星或读秀下载的、用国产工具处理过的、很大的。mulu 只读这些书，不会修改、复制或上传。
2. 生成目录页清单：

   ```bash
   cd mulu   # 进入 mulu 仓库目录
   tools/gate/run_gate.sh ~/你的书文件夹 --make-csv
   ```

3. 打开 `tools/gate/toc_pages.csv`，在 `toc_pages` 一列填上印刷目录所在的**物理页**。物理页就是「预览」侧边栏缩略图下面的页码，例如 `5-7`。不想测的书留空。
4. 再运行一次：

   ```bash
   tools/gate/run_gate.sh ~/你的书文件夹
   ```

   每本书通常几秒到一分钟，脚本已经用 `nice` 降低了优先级。子文件夹里的书要加 `--recursive`。
5. 看结果：终端最后一行 PASS 表示写入失败的书不超过 2 本。**只要出现一本 BROKEN（有输出但读出来不对），就必须排查。**对每本自动生成的目录，逐条对照书上的目录检查三件事：标题认对了没有，层级对不对，点开后是否跳到正文的对应页。
6. 把 `tools/gate/reports/` 里的 `.md` 报告发给开发者。书名不方便透露的话，可以先替换掉。

真实扫描的结果才决定 mulu 能不能用。上面合成书上的数字只能说明「最好的情况下能做到什么」。
