# 真实扫描书闸门（real-scan gate）

用你自己手里的扫描书检验 mulu：写入器能不能在真书上稳定地加上目录，而且一个原字节都不改。

## 它会做什么，不会做什么

- **只读你的书**：不复制、不移动、不修改、不上传。每本书的输出写到系统临时目录（权限 0700），检查完立刻删除；全部跑完后整个临时目录也删掉。
- 每本书依次做：
  1. `mulu info`：页数、交叉引用类型、是否加密、原来有没有目录。
  2. `mulu apply`：写入一份 5 条、3 层的测试目录，分别指向第一页、1/4、1/2、3/4 和最后一页。
  3. 检查输出：
     - 输出开头与原书逐字节相同，原书的 SHA-256 前后不变；
     - 五个独立阅读器（PDFKit、qpdf、PDFium、pypdf、pdf.js）和 mulu 自己读出的目录，与写入的 5 条完全一致；
     - qpdf 语法检查没有新问题。
  4. （可选）如果你在 CSV 里填了这本书目录所在的页，还会跑 `mulu detect-offset` 和 `mulu auto`，把自动生成的目录印在报告里，供你人工核对。这一步不计入结论。
- 只写一份报告：`tools/gate/reports/gate-<时间>.md`，同名 `.json` 放在旁边。报告里有你的书的文件名，只保存在本机。
- 联网：第一次运行时，uv 可能会下载 Python 依赖（pikepdf、pypdf、pypdfium2）。如果 `tools/verify/pdfjs/node_modules` 不存在，还会用 npm 安装 pdf.js。这两步下载的都是工具，你的书不会被上传。
- 运行时用 `nice` 降低优先级，一次只处理一本书，不会让电脑明显变卡。

## 你要做的事

### 1. 准备一个文件夹

把想测的 PDF 放进同一个文件夹，也可以直接用你现有的书库文件夹（只读，不会改动）。建议 10 到 30 本，来源尽量分散：扫描仪直接输出的、超星或读秀之类下载的、用国产 PDF 工具处理过的、出版社电子版、很大的（几百 MB）。子文件夹里的书要加 `--recursive`。

### 2. 运行

在终端里执行：

```bash
cd mulu   # 进入 mulu 仓库目录
tools/gate/run_gate.sh ~/你的书文件夹
```

脚本会先编译 mulu（`swift build -c release`），然后逐本检查。每本书通常几秒到一分钟。终端里每本书会显示一行，比如 `PASS`、`REFUSED` 或 `BROKEN`。

### 3.（可选）顺便试一下自动生成目录

```bash
tools/gate/run_gate.sh ~/你的书文件夹 --make-csv
```

这会生成 `tools/gate/toc_pages.csv`，里面列出了文件夹里的每一本书。用 Numbers 或任意文本编辑器打开，在 `toc_pages` 这一列填上印刷目录所在的**物理页**：用"预览"打开 PDF，看侧边栏缩略图下面的页码，例如 `5-7`，或者 `5,6,8`。不想试的书留空即可。然后再运行一次：

```bash
tools/gate/run_gate.sh ~/你的书文件夹
```

`tools/gate/toc_pages.csv` 存在时会自动使用；也可以用 `--toc-csv 其他路径.csv` 指定。

### 4. 看结果

终端最后一行是结论：

- **PASS**：写入失败的书不超过 2 本。
- **FAIL**：超过 2 本。

"写入失败"分三类：

| 类别 | 含义 | 要不要紧 |
|---|---|---|
| 拒绝（REFUSED） | mulu 明确拒绝处理（例如加密的 PDF），退出码为 2，不产生输出，原书不受影响 | 安全，但这本书暂时用不了 mulu |
| 输出有误（BROKEN） | 产生了输出，但某个阅读器读出的目录或页数不对、有新警告，或者前缀不一致 | **哪怕只有一本，也要排查** |
| 异常（ERROR） | mulu 或检查脚本本身出错 | 需要排查 |

报告的路径印在终端最后，里面有每本书的逐项结果、每个失败的原因，以及（如果填了 CSV）自动生成的目录。请把 `.md` 报告发给开发者。如果文件名不方便透露，可以先把书名替换掉再发。

自动目录这一部分请逐条对照书上的目录，看三件事：标题有没有认错，层级对不对，点开以后是不是跳到了正文的对应页。`mulu auto` 在没把握时会直接拒绝（退出码 2），不会乱猜，报告里会写明原因。

## 其他参数

| 参数 | 作用 |
|---|---|
| `--recursive` | 也检查子文件夹里的 PDF |
| `--toc-csv 文件` | 指定目录页 CSV（格式为 `file,toc_pages`，以 `#` 开头的行是注释） |
| `--report 路径.md` | 指定报告的位置 |
| `--keep-temp` | 保留临时输出，用于调试。注意：这些文件是整本书的完整副本，用完请删掉 |

## 验证这个闸门本身

`tools/gate/selftest.sh` 用生成的样书和两个"故意写坏"的假 mulu 做对照：一个在前缀里改一个字节，一个把第 3 条的页码加 1。两种情况都应判为 BROKEN，结论为 FAIL；用真的 mulu 时应为 PASS，加密样例判为 REFUSED。脚本最后打印 `selftest: ALL OK` 即表示闸门本身可信。整个过程不涉及你的书。

```bash
tools/gate/selftest.sh
```

用到的样书是 `Fixtures/generated` 里的 4 个生成样例，它们不进 git：刚克隆的仓库里没有时，脚本会先运行 `tools/fixtures/make_fixtures.py` 生成（约 10 秒）。如果已经跑过 `tools/run_all.sh --books`，还会加上一本合成扫描书 `Fixtures/books/zh_finance_small_jpeg.pdf`；没有这本书时脚本会打印一行说明并跳过它，自检照样有效。
